# 简明中文 Clear Chinese (CC-ZH 1.0)

> 一份给大语言模型的中文写作受控规范。
> 灵感来自 Andrej Karpathy 的[一条推文](https://x.com/karpathy/status/2105819303471976479)。他建议让 LLM 用 **ASD-STE100**（航空维修手册用的「简化技术英语」）写作。那套规范对文风有极强约束，输出意外地好读。
>
> 问题来了：**中文语境没有 ASD-STE100**。直译一份英文规范没意义，得回到它的**用途**重新设计。

## 30 秒上手

**一句话（最轻）**，对任何大模型说：

> 用简明中文（CC-ZH）写：一句一意，单句不超过 40 字，定语最多两层。不用「进行 + 动词」「被…所…」，不用套话、黑话、排比三连，能量化就量化。

**完整提示词（推荐）**，复制 [prompt.md](prompt.md) 里的「标准档」整段，贴进 system prompt，一次配置长期生效。

**写完检查（可选）**:

```bash
python3 linter.py 你的文档.md
```

零依赖，Python 3.9+，不用装任何东西。

## 一、用途倒推：它到底在解决什么

ASD-STE100 的用途不是「写得漂亮」。它要让母语不同、水平参差的人，执行高风险操作时不误读。靠三件事达成：

| ASD-STE100 的手段 | 真实目的 | 中文语境的等价物 |
| --- | --- | --- |
| 约 900 个核准词，一词一义 | 消除词汇歧义与风格漂移 | 常用词优先 + 术语表锁定 |
| 语法规则（一句一意、句长 ≤ 20 词） | 降低单句记忆负担 | 一句一意 + 30 字上限 |
| 只描述可观察的动作 | 消除模糊与修辞 | 主动语态 + 量化 |

**关键洞察**：中文的病灶和英文不一样。英文受控语言主要治「长句和生僻词」。中文信息密度高、天然句子短，真正的可读性杀手是另外三样：

<!-- cczh:off -->
1. **「的」字链**——「一种基于在训练阶段所引入的多任务学习机制的改进版结构」，定语套定语，读到句尾已经忘了主语。
2. **翻译腔与名词化**——「对该请求进行回收处理」「得以实现」，动词被藏进名词，动作和对象分家。
3. **AI 腔**——排比三段式、「不仅仅是…更是…」、每段开头一个 emoji、破折号后面补半句。这一点英文受控规范里根本没有，但在中文 LLM 输出里是头号污染源。
<!-- cczh:on -->

所以「简明中文」不是 STE 的译本，而是**针对中文病灶重新开的处方**。它的根在中文自己。黄遵宪讲「我手写我口」，叶圣陶讲「写话」：写出来的东西，要能一口气念出来。

## 二、规则（10 条）

编号是为了让 LLM 更容易遵守。发现违规，直接引用编号纠错（「你违反了 CC-7」），比说「写得自然点」有效得多。

### A. 选词

- **A1 · 常用词优先。** 优先使用《现代汉语常用词表》内的词，HSK 四级以内最佳。成语、四字格、生僻词能换成大白话就换。
- **A2 · 一词一义。** 同一个概念全文只用同一个词。原文术语首次出现给「中文（原文）」，之后只用中文。长文档先输出术语表再动笔。
- **A3 · 不造词，不放裸缩写。** 缩写首次必须给全称。不把动词当名词用，这类词见 C10 黑话清单，能换成具体动作就换。
- **A4 · 能量化就量化。** 「很快」→「3 秒内」；「很多」→「超过 200 个」；「大幅提升」→「从 12% 到 40%」。模糊副词是歧义的温床。

### B. 造句

- **B5 · 一句一意，单句 ≤ 30 字**（硬上限 40 字）。数法：汉字逐字数，连续英文/数字串各算 1 个字。超了就拆成两句，别用分号硬连。
- **B6 · 主语在前，动词紧随。** 不省略主语，不把主语埋在状语后面。读者应该在前 8 个字里就知道「谁在干什么」。
- **B7 · 定语最多两层。** 一句里出现三个以上「的」就拆句，或者改写成「主语 + 动词」结构。
- **B8 · 主动优先。** 禁用「被…所…」「得以…」「进行 + 动词」「作出 + 动词」。直接写动词：`进行验证` → `验证`。
- **B9 · 段首是结论，一段只讲一件事。** 先给答案再给理由。需要分点时，每点是一个完整句子，不是一个词。

### C. 语气（去 AI 味）

- **C10 · 禁用清单：**

| 类别 | 禁用 |
| --- | --- |
| 套话 | 值得注意的是、众所周知、在当今时代、随着…的不断发展 |
| 三段式 | 不仅仅是…更是…、既…又…还…、排比三连 |
| 黑话 | 赋能、抓手、闭环、颗粒度、对齐、生态位、护城河（字面义除外） |
| 空形容词 | 深度的、全面的、极致的、颠覆性、革命性、赋能式 |
| 模糊词 | 基本上、某种程度上、一定程度上、相对而言（直接写不确定度） |
| 排版污染 | 每段开头一个 emoji、破折号做解释、括号内补半句、通篇「首先/其次/最后」 |
| 连接词 | 与此同时、因此可见、综上所述（能用句号分开就别连接） |

- **C10 · 配额表**（限量不禁用；严谨档全部归零）:

| 项 | 上限 | 说明 |
| --- | --- | --- |
| 非常 / 极其 / 十分 / 相当 | 每 500 字 2 个 | 「很」不限 |
| 类比 / 比喻 | 每千字 1 个 | 须帮助理解；linter 不查，人查 |
| 排比（不仅…而且…） | 每篇 1 个 | |
| 「之一」 | 每篇 2 个 | 「最成功的公司之一」是正常中文 |
| 「进一步」 | 每篇 1 个 | |
| 「被」字句 | 每段 1 个 | 须明确施动者 |

**输出前自检三问**（写完逐句念一遍）:

1. 这句话能一口气念完吗？
2. 删掉某个词，意思会不会变？不会变就删。
3. 有没有一个词只是「好看」而没有信息？

## 三、示例：Before → After

**1. AI 腔**

> ❌ 在当今快速演进的技术生态中，值得注意的是，大语言模型的能力边界正在被持续拓展，其不仅能够实现高效的内容生成，更可以在复杂推理任务中展现出颠覆性的潜力，而这就要求我们对其输出进行更加全面与深度的理解。

> ✅ 大语言模型正在变强。它能写长文，也能做复杂推理。所以我们花在「读懂它的输出」上的时间会越来越多。

**2. 翻译腔 + 名词化**

> ❌ 当系统监测到由用户所触发的异常请求行为时，将自动对该请求所关联的全部会话资源进行回收处理。

> ✅ 系统发现异常请求后，会回收这个请求占用的所有会话资源。

**3. 「的」字链**

> ❌ 我们采用了一种基于在训练阶段所引入的多任务学习机制的改进版注意力结构。

> ✅ 我们改了注意力结构。它在训练阶段引入多任务学习。

**4. 模糊 vs 量化**

> ❌ 这个方案的性能提升非常明显，响应速度也变得很快。

> ✅ 这个方案把吞吐从 120 QPS 提到 480 QPS，响应时间从 800ms 降到 90ms。

## 四、三档严格度

Karpathy 有个很实用的技巧：要「80% 的 ASD-STE100」，因为原规范太严。中文版同样需要软化开关。

| 档位 | 适用 | 放宽了什么 |
| --- | --- | --- |
| **CC-ZH 严谨档** | SOP、教程、法律、医疗、事故复盘 | 30 字上限严格执行，零修辞，C10 全禁 + 配额归零 |
| **CC-ZH 标准档**（默认） | 技术文档、解释性回答、代码注释 | 同上，但允许必要术语与被动句；配额生效 |
| **80% CC-ZH** | 博客、观点文、分享 | 允许比喻、个人语气、较长句；仍保留「一句一意」和 C10 禁用清单 |

一句话切换：**「用 80% 简明中文写」**，通常就够了。

## 五、直接复制：提示词

见 [prompt.md](prompt.md)。标准档整段如下：

````md
# 写作规范：简明中文 CC-ZH 1.0

你用「简明中文」写作。目标不是文采，而是让读者一眼看懂、没有歧义、可以照着做。

## 硬规则
1. 一句一意。单句不超过 30 字，最长 40 字。超了就拆成两句。
2. 主语写在句首，动词紧跟主语。不省略主语。
3. 定语最多两层。一句里三个以上的「的」就拆句。
4. 一个概念全文只用一个词。术语首次出现给「中文（原文）」，之后只用中文。
5. 用常用词。成语、四字格、生僻词能换成大白话就换。
6. 能量化就量化。「很快」→「3 秒内」；「很多」→「超过 200 个」。
7. 主动优先。禁用「被…所…」「得以」「进行 + 动词」「作出 + 动词」。
8. 段首第一句是结论。一段只讲一件事。
9. 配额：「非常/极其/十分/相当」每 500 字最多 2 个；类比每千字最多 1 个；排比每篇最多 1 个；「被」字句每段最多 1 个。
10. 严格度：默认标准档。若我说「80% 简明中文」，允许比喻和个人语气，但仍遵守第 1 条和下面的禁用清单。

## 禁用清单
- 套话：值得注意的是、众所周知、在当今时代、随着…的不断发展
- 三段式：不仅仅是…更是…；排比三连
- 黑话：赋能、抓手、闭环、颗粒度、对齐、生态位、护城河（字面义除外）
- 空形容词：深度的、全面的、极致的、颠覆性、革命性
- 模糊词：基本上、某种程度上、一定程度上、相对而言（直接写不确定度）
- 排版污染：每段开头一个 emoji、破折号做解释、括号内补半句、通篇「首先/其次/最后」
- 连接词：与此同时、因此可见、综上所述（能用句号分开就别连接）

## 输出前自检
写完逐句念一遍，问自己三件事：
1. 这句能一口气念完吗？
2. 删掉某个词，意思变吗？不变就删。
3. 有没有哪个词只是好看、没有信息？
把不合规的句子改掉再输出。
````

## 六、linter：写完机械初筛

```bash
python3 linter.py 文档.md                # 标准档（默认）
python3 linter.py --level 100 文档.md    # 严谨档
python3 linter.py --level 60 文档.md     # 80% 档
python3 linter.py --json 文档.md         # 结构化输出
```

能查：黑名单（C10）、句长（B5）、「的」链（B7）、「进行 + 动词」「被…所…」「得以」（B8）、段首 emoji、配额超标。
查不了：量化是否到位、类比是否恰当、术语是否一致。机械初筛 + 人工判断，零违规不等于好文章。

豁免：代码块不查；「❌」开头的示例行不查；表格行不查；`<!-- cczh:off -->` 到 `<!-- cczh:on -->` 之间不查。

本 README 自身通过标准档检查（硬违规 0）。

## 七、往上三层：图 / 网页 / 视频

写作只是第一层。Karpathy 的完整阶梯是：**文字 → 图 → 网页 → 视频**。后面的三层不需要重新设计语言规范，但中文语境有几个专属坑：

- **图（SVG / Mermaid）**：图内文字用中文，字体指定 `Noto Sans SC` 或思源黑体。术语和正文术语表一致。中文标签比英文长，节点留 1.5 倍宽度。
- **网页（单文件 HTML）**：中文排版要单独调。行高 1.8，段间距大于行距。中西文之间自动加细空格（`text-autospace`），标点避头尾。默认给暗色模式，移动端优先。
- **视频（Manim / 3b1b 风格 + TTS）**：中文 TTS 语速降到 0.9 才自然。配音稿给英文缩写和数字补发音提示，比如 `GPT` 写成「G-P-T」，否则读出来必然翻车。字幕不要直接复用旁白文本，中文字幕每屏 ≤ 15 字。

## 八、常见坑

- **短不等于少。** 简化是为了清晰，不是为了让答案变薄。拆句之后信息量应该不变甚至更完整。
- **别矫枉过正。** 「严谨档」写给人类读者会显得冷冰冰。分享类内容默认用 80% 档。
- **术语表先行。** 超过 1000 字的文档，先让 LLM 输出术语表并确认。再让它按表写作，一致性提升最明显。
- **一次性纠错。** 发现 AI 腔时，别说「写得自然一点」，没用。直接说「违反 C10，改掉」。LLM 对编号规则的服从度高得多。

## 九、同赛道项目

Karpathy 发帖后，中文社区出现了几个同类项目。它们管**技术文档**的术语精确性，CC-ZH 管**说明文**的可读性，场景互补：

| 项目 | 定位 |
| --- | --- |
| [mzopedia/simplified-technical-chinese](https://github.com/mzopedia/simplified-technical-chinese) | 技术文档受控中文，40 条规则 + 词表，350 万字校准 |
| [lemonhall/asd-ste100-skill-zh](https://github.com/lemonhall/asd-ste100-skill-zh) | agent 间技术文本改写，确定性 linter |
| [noahwang550/zh-plain](https://github.com/noahwang550/zh-plain) | 中文受控语言，消歧义 + 去 AI 味 |

CC-ZH 的差异：三档提示词复制即用、配额制（限量不禁用）、零依赖 linter、覆盖图/网页/视频层。

ASD-STE100 是注册商标。本项目与其无关，不表示符合本规范的文本符合 ASD-STE100。
